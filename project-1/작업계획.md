## 실행 단계

### 0. 접근 방식
- 기존 `cnn-trafficsign-torch-skeleton.ipynb`를 완성하는 방식
- 스켈레톤에 이미 포함된 코드: 임포트, seed 설정, 데이터 로딩 (Train only)
- 추가 구현: Val 분할, Dataset/DataLoader, 모델, 학습, 추론, CSV 출력

### 1. 환경 설정
- conda env: `gpu-torch`
- `gpu_test.py` 실행하여 GPU 사용 가능 여부 확인
- 필요 패키지: torch, torchvision, opencv-python, numpy, pandas, scikit-learn, Pillow, matplotlib (requirements.txt 참조)

### 2. 데이터 전처리
- **경로 수정**: 스켈레톤의 `./data/Train/` → 실제 경로 `./dataset/data 2/Train/`

- Train/Val 8:2 stratified split (class 비율 유지)
- PyTorch `Dataset` / `DataLoader` 구현 (batch_size, shuffle)
- Class imbalance 대비 `compute_class_weight` 적용
- Test 데이터도 동일 전처리 파이프라인

### 3. CNN 모델 설계
- Conv-BN-ReLU-MaxPool 블록 2~3개
- Dropout 적용 (overfitting 방지)
- Fully Connected → 43 class 출력

### 4. 학습 루프

- Best model 저장 (val accuracy 기준)

### 5. 추론 및 결과 저장

## 히스토리 요약 (반복 학습 진행 과정)

### iter16 (데이터 정제 실험)
- **개요**: 전체 데이터(26,010장)가 아닌, Track당 최대 5장만 샘플링하여 4,340장으로 압축(Pruning).
- **결과**: ConvNeXt(Pretrained)는 99.35% 정확도 방어, Scratch CNN은 40%로 붕괴. (최종 2-Model 앙상블 99.39% 달성)
- **분석결과**: [iter16_report.md](./iter16-pruned/iter16_report.md) 참조

### iter17 (대조학습 SupCon 도입)
- **개요**: 데이터 부족으로 무너진 Scratch 모델을 512D 특징 공간의 대조학습(SupCon)을 통해 구제할 수 있는지 테스트.
- **결과**: ConvNeXt는 99.2% 수준을 유지했으나, Scratch CNN은 여전히 40%대(F1 0.31)로 붕괴.
- **분석결과**: [iter17_report.md](./iter17-supcon/iter17_report.md) 참조
- **결론**: 극한의 데이터 기근 환경에서는, 아무리 우수한 최신 Loss(SupCon)를 적용해도 Pretrained 모델의 힘을 대체할 수 없음 (The Bitter Lesson).

### iter18-final (최종 4-Model 엘리트 앙상블)
- **개요**: iter17의 뼈아픈 실패를 교훈 삼아, Scratch 모델을 완전히 퇴출.
- **적용**: 100% Pretrained 가중치를 가진 엘리트 4종 모델(ConvNeXt, ResNet50, EfficientNet-B0, MobileNetV3)을 5-Fold로 학습 후 가중 앙상블 적용.
- **결과**: Test Acc 98.92%, Macro F1 0.9839.
- **결론**: 데이터 절약(1/6)에도 98.9% 달성. 다만 하위 경량 모델들이 평균 점수를 깎아내림.

### iter19-hero (단일 영웅 모델 SOTA 도전)
- **개요**: iter18의 교훈을 바탕으로, 앙상블을 해체하고 가장 성능이 좋은 `ConvNeXt` 1개에 모든 자원 집중.
- **적용**: 원본 데이터 100%(26,010장) + 대조학습(SupCon) + 5-Fold.
- **현재 진행상태**: 대망의 최종 SOTA 갱신을 향해 백그라운드 학습 진행 중...
