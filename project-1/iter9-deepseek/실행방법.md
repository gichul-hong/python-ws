## 실행 직후 확인할 것 (2가지)

### 1. 트랙 파싱 및 fold 배분 (시작 3분 내 출력)

```
Total: 26010 images, 868 unique tracks
fold 0:   8670 imgs, 290 tracks, small-class val tracks min=2 max=2
fold 1:   8670 imgs, 289 tracks, small-class val tracks min=2 max=2
fold 2:   8670 imgs, 289 tracks, small-class val tracks min=2 max=2
```

- `868 unique tracks` — 정상 (26,010 ÷ 30프레임)
- **`small-class val tracks min=2`가 핵심**입니다. iter8은 소수 클래스에 val 트랙이 1개뿐이어서
  클래스 11→30 오분류를 전혀 잡지 못했습니다. 2개 이상이면 측정 가능해집니다.
- `[WARN] track parse failed`가 나오면 즉시 알려주세요 (파싱 오류)

### 2. fold 0의 초기 epoch

```
[fold 0] Epoch   1/20 | Val Acc 0.96xx F1 0.96xx
```

epoch 1에서 F1이 0.9 이상이면 정상입니다 (ConvNeXt는 iter8에서 ep1에 0.9680).
0.5 이하로 나오면 설정 문제이므로 중단하고 알려주세요.

## 이번 실행에서 얻는 것

1. **OOF Macro F1** — 26,010장 전체를 각각 "그 이미지를 학습하지 않은 모델"이 예측한 결과.
   단일 20% hold-out보다 신뢰도가 높고, 소수 클래스도 fold당 2트랙으로 평가됩니다.
   앞으로 이 값을 기준으로 개선 여부를 판단합니다.
2. **전체 데이터 혼동 행렬** — 클래스 11→30이 실재하는지, 다른 취약 쌍이 있는지 확정
3. **제출 후보** — 3-fold 모델 앙상블 예측(`result.csv`) + 분포 프록시 비교

## 설정 요약 (iter6 대비 변경점을 1개로 제한)

| 항목 | iter6 (test 0.9892) | iter8 (실패) | **iter9** |
|------|--------------------|--------------|-----------|
| 아키텍처 | ResNet-50@96 | 3종 앙상블 | **ConvNeXt-Tiny@96** |
| 해상도 | 96 | 96/128 | **96** (원본 중앙값 42px → 96이 상한) |
| GaussianBlur | k=3, σ≤1.0, 소수만 | **k=5, σ≤2.0, 전체** | **제거** |
| 저해상도 시뮬레이션 | 없음 | **p=0.25** | **제거** |
| ColorJitter | 0.3 / 0.4 | 0.5 | **0.3 / 0.4** (iter6과 동일) |
| 검증 | random 20% (누수) | track 20% (소수클래스 1트랙) | **track 3-fold (소수클래스 2트랙)** |
| Epochs | 30 | 30 | 20 |

증강을 iter6 수준으로 되돌리고 아키텍처만 교체했으므로, OOF 지표로 ConvNeXt 교체의
순효과를 판단할 수 있습니다.

## 참고: 조정 가능한 설정

`train.py` 상단 상수로 조정합니다.

- `CLASS_WEIGHT_MODE = 'balanced'` → `'sqrt'`
  balanced + 2x 오버샘플링은 소수 클래스에 완전 균형(약 7배)을 적용합니다.
  OOF 혼동 행렬에서 다수→소수 클래스 유출(예: 11→30)이 관측되면 `'sqrt'`로 완화해 재실행합니다.
- `EPOCHS = 20` → fold별 best epoch이 18~20에 몰리면 수렴이 덜 된 것이므로 25로 상향
